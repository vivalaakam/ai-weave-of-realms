# Tile Rendering System

Rendering lives in `crates/rpg-embedded/src/render.rs`. The crate is `no_std + alloc` and uses `embedded-graphics` as
the draw abstraction.

---

## Atlas format (`assets/tiles.bin`)

Generated by `cargo run -p rpg-tools --bin pack-tiles`.

```
[magic:  4 bytes]  b"RPGT"
[tile_w: 1 byte ]  u8  (currently 16)
[tile_h: 1 byte ]  u8  (currently 16)
[count:  4 bytes]  u32 LE
[mask_0: 32 bytes] bitmask for tile 0
[mask_1: 32 bytes] ...
```

Each mask is `ceil(16 × 16 / 8) = 32` bytes. Pixels are stored row-major, MSB-first:
pixel `(x, y)` → bit `y * 16 + x`; byte index `bit / 8`, bit position `7 - bit % 8`.

PNGs are packed in **alphabetical filename order**. Within each PNG tiles scan left→right, top→bottom. A pixel is "set"
when `alpha >= 128`.

Current atlas layout:

| Filename          | Start index | Count | Notes                    |
|-------------------|-------------|-------|--------------------------|
| `1_main.png`      | 0           | 1078  | main tileset             |
| `2_water.png`     | 1078        | 5     | water autotile pieces    |
| `3_mountains.png` | 1083        | 5     | mountain autotile pieces |

## Drawing a cell

`draw_cell` (called per visible tile each frame):

1. Fill the tile rectangle with the base **terrain color** (`theme.tile_color`).
2. Draw the terrain **sprite overlay** (`theme.tile_sprite_color`) using `draw_grass_sprite`, which iterates the bitmask
   and emits pixels scaled from 16×16 → 32×32.
3. Draw entity markers on top (hero, city, enemy spawn, chest).

The `visible_cells` cache stores a `u32` signature per screen slot. If the signature matches the previous frame the cell
is skipped entirely.

## Water autotile system

### Source tiles (`assets/2_water.png`, 5 × 16×16 px)

| Index (0-based) | Atlas index               | Description                                |
|-----------------|---------------------------|--------------------------------------------|
| 0               | 1078 `WATER_FULL`         | Full 16×16 rectangle — all pixels set      |
| 1               | 1079 `WATER_SHORE_LL`     | Shore piece: **lower-left** half of W edge |
| 2               | 1080 `WATER_SHORE_UL`     | Shore piece: **upper-left** half of W edge |
| 3               | 1081 `WATER_CORNER_OUTER` | Outer corner: diagonal cut at upper-left   |
| 4               | 1082 `WATER_CORNER_INNER` | Inner corner: 3-pixel notch at upper-left  |

Tiles 1–4 are **fragment pieces** designed to be AND-composited onto tile 0.

### Neighbor encoding

`water_neighbor_bits(map, coord) → u8`

8-bit key, one bit per Moore-neighbourhood direction. **1 = water, 0 = land / OOB.**

```
bit 7  bit 0
NW N NE
 W · E
SW S SE

bit0=N  bit1=NE  bit2=E  bit3=SE
bit4=S  bit5=SW  bit6=W  bit7=NW
```

### Compositing rules

`compute_water_composite(bits: u8) → WaterMask`

Start with `WATER_FULL` (all pixels set). AND-in fragment pieces according to which neighbors are land:

#### Edge pieces — half-edges, skipped when replaced by an outer corner

Each edge is split into two halves so adjacent outer corners can replace them cleanly.

| Condition         | Mask applied | Covers            |
|-------------------|--------------|-------------------|
| W land && N water | `ul`         | W edge upper half |
| W land && S water | `ll`         | W edge lower half |
| N land && W water | `ll90`       | N edge left half  |
| N land && E water | `ul90`       | N edge right half |
| E land && N water | `ll180`      | E edge upper half |
| E land && S water | `ul180`      | E edge lower half |
| S land && W water | `ul270`      | S edge left half  |
| S land && E water | `ll270`      | S edge right half |

`llN` = `SHORE_LL` rotated N × 90° CW; `ulN` = `SHORE_UL` rotated N × 90° CW.

> **Key asymmetry:** after 180° rotation the "lower" piece becomes the upper and vice versa. `ll180` is the *upper* half
> of the E edge; `ul180` is the *lower* half. This is correct and intentional.

#### Outer corners — two adjacent land edges

| Condition   | Mask applied | Covers                        |
|-------------|--------------|-------------------------------|
| W && N land | `co`         | NW outer corner (upper-left)  |
| N && E land | `co90`       | NE outer corner (upper-right) |
| E && S land | `co180`      | SE outer corner (lower-right) |
| S && W land | `co270`      | SW outer corner (lower-left)  |

An outer corner replaces the two "near" half-edges (e.g., NW corner replaces W-upper and N-left). The replacement is
automatic: both those half-edge conditions test `!n` / `!w` respectively, so they are false and skipped.

#### Inner corners — diagonal land only

Applied when both orthogonal neighbors are water but the diagonal is land. Creates a small 3-pixel notch.

| Condition                     | Mask applied | Covers   |
|-------------------------------|--------------|----------|
| W water && N water && NW land | `ci`         | NW inner |
| N water && E water && NE land | `ci90`       | NE inner |
| E water && S water && SE land | `ci180`      | SE inner |
| S water && W water && SW land | `ci270`      | SW inner |

### Rotation function

```rust
fn rotate_cw90(m: &WaterMask) -> WaterMask
// pixel (x, y) → destination (N-1-y, x), N = 16
```

Rotation mapping summary:

| Rotation | Left edge → | Top edge → |
|----------|-------------|------------|
| 0°       | left        | top        |
| 90° CW   | top         | right      |
| 180°     | right       | bottom     |
| 270° CW  | bottom      | left       |

### Cache

`RenderCache.water_masks: Vec<Option<WaterMask>>` — 256 slots (one per 8-bit neighbor key), lazily populated on first
access via `cached_water_mask`. The cache persists as long as the `RenderCache` lives; it is not invalidated on scroll
because the masks depend only on the tile atlas (compile-time data) and the neighbor pattern (encoded in the key).

## Adding a new terrain type

### Simple overlay (forest, flowers, ruins…)

1. Add the PNG to `assets/`. Regenerate `tiles.bin`:
   ```sh
   cargo run -p rpg-tools --bin pack-tiles -- --tile-width 16 --tile-height 16
   ```
2. Add index constants to `render.rs`:
   ```rust
   const MY_INDICES: [usize; N] = [start, start+1, …];
   ```
3. In `draw_cell`, add a branch:
   ```rust
   if matches!(tile.kind, Tiles::MyTerrain) {
       let idx = (coord.x as usize * 31 + coord.y as usize * 17) % N;
       draw_grass_sprite(display, top_left, tile_atlas_mask(MY_INDICES[idx]), color);
   }
   ```

### Autotile (water-style compositing)

Use when a terrain type needs smooth borders against other terrain (rivers, roads, walls, mountains).

**Design the source tiles** (always for the W edge / upper-left corner, then rotate):

| Tile         | What it should look like                               |
|--------------|--------------------------------------------------------|
| FULL         | All pixels set (or full base pattern)                  |
| SHORE_LL     | Terrain present in upper half, border in lower-left    |
| SHORE_UL     | Terrain present in lower half, border in upper-left    |
| CORNER_OUTER | Diagonal cut at upper-left (where two land edges meet) |
| CORNER_INNER | Tiny notch at upper-left (diagonal-only land neighbor) |

**Implementation steps:**

1. Add 5 tiles to PNG → regenerate atlas → add 5 index constants.
2. Add a `MyMask = [u8; TILESET_MASK_BYTES]` type (or reuse `WaterMask`).
3. Copy `compute_water_composite` → rename → adjust the neighbor predicate (e.g., "is it the same terrain type?" or "is
   it passable?").
4. Add a `my_masks: Vec<Option<MyMask>>` field to `RenderCache`.
5. Add a `cached_my_mask` function identical to `cached_water_mask`.
6. In `draw_cell`, call `draw_grass_sprite` with the composite mask.

**Neighbor predicate tips:**

- **River**: neighbor is river OR lake/sea.
- **Road**: neighbor is road (dirt track, cobblestone, etc.); draw border against non-road.
- **Mountain**: neighbor is mountain; draw cliff-edge border toward lower ground.
- **Forest**: typically no autotile needed — discrete sprites look fine. Use random index selection.

### Performance notes

- `compute_water_composite` allocates no heap; all `WaterMask` values are stack arrays.
- The 256-slot `Vec<Option<WaterMask>>` is ~8 KB and populated once per unique neighbor pattern seen.
- `draw_grass_sprite` iterates 256 source pixels and emits up to 1024 target pixels per call (4× scale). For multiple
  overlapping overlay layers, composite the masks before drawing to stay within one `draw_iter` call.
